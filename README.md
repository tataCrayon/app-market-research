# app-market-research

**App / 小程序立项前的全端调研 Skill**——从「我想做一个 X」到「做 / 不改方向 / 先验证什么 / 卡合规 / 放弃」。

> 通用商业调研技能默认「产品做出来就能卖」。移动产品的真实世界里有三堵墙：
> **上架审核、资质备案、平台分成**。每一堵都能把一个「市场很大」的想法变成上不了线、或上线即亏的东西。
> 而这三堵墙按端分裂：微信小程序、iOS、安卓（国内商店群 + Google Play）是三门生意，不是同一个产品的三个壳。

---

## 它解决什么

| 通用市场调研 | 本 Skill 多做的 |
|---|---|
| TAM / SAM / SOM、趋势、人群画像 | 同样做，但 SOM 用**盈亏平衡**判定而非绝对值（App 有明确刚性成本项） |
| 竞品功能对比 | 多查一层：**端覆盖是否等价**（不等价处通常就是真实缺口） |
| — | **Step 0 GATE**：先定端，把「三端全做」设为有罪推定 |
| — | **Step 4 PLATFORM**：三端硬约束七查（上架 / 审核 / 资质 / 能力 / 付费 / 分发 / 周期） |
| — | **延误险**：合规与账号周期是日历天数，与研发**串行**，必须加总写进下一步 |
| 判决：做 / 不做 | 五选一，多一个 **⏸ 卡合规**，并强制附「最便宜的验证 + 放弃信号」 |

---

## 六步循环

```
GATE     — 先定端：主端 / 副端 / 延后端（端是后续所有约束的自变量）
FRAME    — 压成 2-4 条可证伪主张 + KPI 三级 + 致命风险
MARKET   — TAM/SAM/SOM + 盈亏平衡 SOM + 3-5 条趋势（顺风 / 逆风）
RIVAL    — 竞品四层 → 七层情报 → 对比矩阵 → 桌赌注 / 共性缺口 / 被忽略人群 → 楔子
PLATFORM — 三端硬约束七查（心脏）
VERDICT  — 五选一 + 最值钱的一步 + 最便宜的验证 + 放弃信号
```

## 硬信念（违反即报告作废）

1. **端决定命运**。「先做 App，顺手补个小程序」是最贵的路线：小程序靠社交裂变与搜一搜，App 靠商店榜单与 ASO，几乎不重叠，还与 iOS 付费规则直接冲突。
2. **政策必须现场取证**。审核规则、类目资质、备案要求、分成比例按季度变。每条政策结论必须带**官方链接 + 查证日期**；查不到写「未取证」，且**未取证默认计为风险**。
3. **差评比官网可信十倍**。竞品功能页是广告；一星评论和**近 6 个月更新日志**才是真相。
4. **判决必须落地**。禁止以「值得考虑」收尾。

## 证据分级（这条是被教训出来的）

| 级别 | 来源 | 用法 |
|---|---|---|
| ① 权威 | 监管部门官网原文 | 政策结论只基于这层 |
| ② 平台官方 | 应用商店 / 门户开发者文档 | 上架门槛基于这层 |
| ③ 二手 | 资质代办机构与 SEO 博客 | **只能当线索**，不得当结论；只有它时标 ⬜，并转成「打电话确认」的待办 |

## 输出

产出一份 Markdown 立项调研报告，骨架见 `SKILL.md` 的「输出格式」。核心是三张表：

- **端阵决策**（主端 / 副端 / 延后端）
- **政策快照表**（七查 × `结论 | 出处 | 查证日期 | 状态 ✅/⚠️/🔴/⬜`），阻塞项未清零前不得判「立项」
- **判决**（五选一 + 最值钱的一步 + ≤1 天验证 + 放弃信号）

## 文件结构

```
SKILL.md                                    主流程 / 输出模板 / 红线 / 与其他 Skill 的关系
references/three-platform-constraints.md    三端七查清单 + 查证入口（故意不写死政策数字）
references/research-sources.md              中国移动端数据源 + 检索语句模板
```

> 参考文件**故意不写具体政策数字**——任何写死的数字都会在下一次调研时变成假证据。

## 与其他 Skill 的接力

```
app-market-research（要不要做 / 哪端做 / 有没有硬阻塞）
  → grill-me（做什么 / 边界）
  → grill-method（怎么做 / 路线）
  → fullstack-spec（版本化需求文档）
```

- 通用技术 / 流程 / 工具想法体检 → 用 `idea-vetting`，不是本 Skill（本 Skill 只管移动端 / 小程序立项）。
- 已决定要做 → `fullstack-spec`、`design-director`、`ui-craft`。
